# 数学密集 PDF 的实测问题

2026-11-18：以一篇 51 页、含 101 个编号公式、6 幅矢量图、9 张表和跨页 Python 代码的论文完成重建。这里记录通用问题，不在 skill 中保存作者信息或论文正文。

1. PDF 文本提取会把上下标、分式和多行对齐公式打乱，即使页面有大量可选择文字。新增 `pdf_inventory.py` 保留每个字形的字体、大小、位置和基线矩阵，并标记数学、代码及不可映射字形。
2. 同一数学表达式可混合 CM 数学字体与罗马数字、字母、算子。不能仅按字体切分而把 `CN`、转置 `T`、`sin`、`log` 排除在公式外。数学候选检测只能辅助人工/模型重建。
3. 正文换行后以“5.4”“5.6”开头不能直接视为标题。应与字号、字体、实际目录交叉核对。生成目录与原目录逐项比对，而非仅确认目录不为空。
4. 公式中夹中文“即”等词时仍可能是编号陈列公式。核对全部公式编号和引用，防止将右端编号误变成一个悬空引用。
5. 代码跨页时，平面文本丢失缩进。根据等宽字符横坐标复原，用静态语法解析核验，不执行文中实验命令。用 `fvextra` 的可断行 Verbatim 排版长代码；仅在使用时列明该依赖。
6. `gb7714-2015` 的 online 类型可能不输出已填写的 DOI。核对最终参考文献，必要时用 `addendum={DOI: ...}` 保留原文信息；检查是否重复。按原文保留全部作者时显式设置 `maxbibnames`，不擅自扩展姓名缩写。
7. 封面长题名按语义断行，不能把“能量”等词拆开后就结束验收。元数据包含 `\\` 时还需清理 PDF 书签字符串中的换行命令。
8. 单独保留原 PDF、图形区域、源页到生成内容的映射，以及绑定最终 PDF 哈希的审核记录。中文字符序列一致只证明该部分文字保留，不能证明数学和视觉内容正确。
9. 重建段落时可显式输出 `\par`，并对照最终 PDF 的缩进检查段落边界。英文关键词可将单个词组放入 `\mbox`，关键词分隔宏必须允许在词组之间换行；模板现用显式可断行的三字宽间距，避免长词表越界。
